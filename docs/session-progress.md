# 工作进展：从 OpenViking 会话归档查看当前状态

日期：2026-09-22
状态：已实现，验收记录。

## 用户体验

工作台导航顺序为“目录 → 工作进展 → 报告与洞察”。工作进展页描述为“基于 OpenViking 内的所有 Session 信息，展示你当前的工作进展”。

页面直接读取当前连接用户的会话归档，不再依赖 Agent 手动发布的 workspace.json 工作卡片，也不使用 Codex 本地会话或临时接续简报代替云端数据。

每个 Session 一张横向大卡，展示最新 archive L1 中的 Session Title、Current State，以及“上次抽取记忆”。时间取这份 `.overview.md` 文件的 modTime，以浏览器本地时区显示。卡片按 L1 更新时间倒序排列，每页 20 项，支持按标题、进展搜索。

点击“展开概览”读取完整 L1，不截在 200 行。预览清理 Markdown 脚本，生成元数据保留在云端原文，不混入卡片标题与状态。全文按需读取，默认只展示简要状态。

不再出现“本轮核对的工作接续简报”入口。侧边页面提供“复制接续指令”，粘贴到 Codex 后核对最新归档、回顾目标和进度、建议推进方向，等待用户下一条指令再执行。App 宿主支持发送消息时可直接“回顾进展，选择下一步”。

## 数据来源和缺口

当前个人版标准路径：`viking://user/default/sessions/<session_id>/history/archive_<number>/.overview.md`。身份来自已验证配置，当前插件支持 default。

列出当前用户 sessions 下全部会话目录，再从每个 history 目录按 archive 数值编号选最新节点。例如 archive_1000 比 archive_999 更新，不依赖字符串排序。不会静默回退到旧归档、实时消息或本地摘要。

目录、会话或 archive 的更新时间都不能替代 L1 文件更新时间；取不到该字段时展示“时间未知”。尚无归档的会话保留“尚未生成归档概览”，读取失败保留错误状态。旧 L1 若只有消息数量，没有 Session Title / Current State，保留 Session ID 与缺失提示，可展开原文，不自动编造工作总结。

本次真实库读取到 29 个会话：28 个有可读的最新 L1，1 个无 archive；28 份 L1 中有 2 份仅含消息统计，无法提取业务标题与当前状态。这属于源数据内容缺口。

## 大量会话

后台只读索引使用最多 4 个并发请求，分批更新完成数；初始页面可先展示上次缓存。浏览器每 2.5 秒检查更新进度，完成后停止轮询。分页、搜索在索引侧进行，每次只向页面返回 20 项，全文在展开时单独读取。

缓存按连接身份隔离，密钥不会下发前端或存入索引。每次更新重新核对最新 archive 和 L1 modTime，只有二者均未变化时复用旧正文。同一连接只允许一个扫描任务；读取中断可刷新重试，失败不会伪装为“0 个会话”。连接变更后新页面只读取新连接的索引。

公有云目录接口当前使用高 node_limit 获取全量清单，避免默认 1000 节点或负数截断。浏览分页不等于服务端目录接口具有游标分页；若单次目录响应超过客户端 16 MB 上限，会明确失败，需要后续服务端分页支持，不宣称无容量上限。

## 实现和验收

- `session_progress.py`：全量目录读取、最新 archive 选择、L1 字段解析、时间校验、身份隔离缓存、后台扫描与分页查询。
- `src/progress.mjs`：横向卡片、搜索分页、状态轮询、全文展开、复制接续指令。
- `get_session_progress` / `read_session_overview`：只读 App 工具，对应侧边页面的本机 HTTP 接口；没有新增记忆抽取、commit 或上传动作。
- 新模块包含在 MCP 运行时快照中；面板构建指纹包含 Python 后端，升级后不复用过时后端进程。

58 项 Python 测试与 4 项真实 MCP 测试通过；浏览器覆盖云端来源替换、横向布局、导航顺序、轮询、45 项分页、搜索、240 行全文、读取错误重试、脚本清理、复制接续指令和窄侧栏。Python 额外覆盖 1051 个会话、数值 archive 排序、mtime 缓存失效、跨连接隔离与缺失字段。原有目录、onboarding 与接续卡片回归通过。

公有云只读取既有会话。本仓库截图使用虚构数据，不包含真实会话内容。没有声称执行过所有后续任务或重新抽取过历史记忆。
