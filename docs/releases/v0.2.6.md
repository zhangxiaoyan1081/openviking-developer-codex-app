# OpenViking Codex App v0.2.6

修复普通任务中查询 OpenViking 用户绑定时意外展示用户卡片的问题。

## 更新

- `list_bound_users` 改为只返回绑定数据，不携带 App 卡片元数据，不推进接入流程。即使留有未完成的绑定，也可用于静默查询。
- 新增 `show_bound_users`，仅在用户明确要求查看/管理绑定，或本次绑定引导结束且尚未展示列表时使用。显式打开的用户卡片仍可正常刷新。
- 收紧 Skill 的触发范围：写作、编码、研究、按需检索和资料归档不自动进入 onboarding。遇到身份或权限问题时，不自行打开卡片或切换用户。
- 区分设备默认绑定与当前任务实际使用的云端身份，避免把本机绑定查询当成旧任务已经切换的证据。

## 安装与升级

下载并解压 `openviking-codex-app-v0.2.6.zip`，在解压目录执行：

```bash
python3 install.py --companion-only
```

需要 Python 3.10+、Node.js 22+、Git 和 Codex；分发包已有构建资源。更新保留用户绑定、凭据和官方记忆插件。

更新后重启 Codex，再继续正常工作，无需重新接入或提交 API Key。旧任务已显示的卡片不会被撤回；若旧任务仍使用历史工具定义，请新开任务。需要查看绑定时，可直接说“查看已绑定的 OpenViking 用户”。

## 验证与范围

- 新增真实 MCP 协议回归：未完成绑定时重复查询不返回 UI 元数据或 view、不泄露 Key、不改变连接或接入状态；显式展示入口仍返回用户卡片。
- 浏览器回归覆盖显式用户卡片的数据刷新，不额外发送 Agent 消息；同时保留接入、工作台目录和工作进展回归。
- 本机实际安装入口验证 0.2.6 的静默查询、展示工具元数据和 HTML 资源；安装前后连接、绑定及官方 Hook 配置一致。
- 此次验证覆盖工具协议、模拟宿主浏览器和本机安装入口，未重放完整 Codex 原生业务对话。Skill 触发规则由 Agent 遵循；不宣称能阻止模型误用所有展示工具。

Release 由 GitHub Actions 在 Python、MCP 和浏览器验收通过后发布。附件包含分发 ZIP 和 `SHA256SUMS`，不包含个人配置、凭据或历史会话。
