# Codex 程序路径迁移：用户切换修复

日期：2026-10-08  
版本：0.2.5  
源码：[hook_setup.py](../plugins/openviking-codex-app/scripts/hook_setup.py)、[安装器](../install.py)、[切换器安装器](../scripts/install-switcher.py)。

## 原因与影响

测试任务「接入 OpenViking」显示：新 Key 已通过云端身份及目录验证，绑定也已经保存；启用前的本机隔离检查失败，原连接保持不变。

本机 Codex CLI 为 `0.162.0-alpha.2`。旧位置 `/Applications/ChatGPT.app/Contents/Resources/codex` 已不存在，新位置是 `/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex`。

旧安装器将当时的绝对路径写入 App 的 `OV_APP_CODEX`，切换器启动脚本也写死该路径。`hook_setup.codex()` 无条件优先读取该值，不检查文件是否有效，因此 PATH 中已有新程序也不会使用。失败发生在插件/Hook 检查阶段，不是 API Key 鉴权阶段。笼统的“核对连接、范围或清单”提示让用户误以为需要重新输入 Key。

此前测试任务已手工修正本机配置路径并成功启用新绑定；本次将适应路径迁移的逻辑补进可分发源码。多用户 0.2.4 源码来自该测试任务的工作副本，已保留其实现并整合到本仓库。本次不以重新切换真实用户来验证修复。

## 0.2.5 行为

每次使用本机 Codex 工具时重新解析：有效的显式 `OV_APP_CODEX` → 该旧路径所属 App 的已知新旧布局 → PATH → 系统与用户 Applications 下的 ChatGPT/Codex 已知布局。候选必须是可执行文件；无效文件、断裂符号链接被跳过。自定义 App 安装位置也可从旧路径的 bundle 推导。

新安装不再自动固化安装当天的 CLI 绝对路径；显式配置仍可保留，但失效后可回退。安装器与宿主检查共用解析逻辑，官方安装子进程使用解析后的程序目录。已有切换器通过 `--host-only` 更新路径发现代码及其启动脚本，不重新安装隔离包装、不写入信任记录。

找不到程序、进程无法启动、提前退出、协议错误和超时，均返回明确的本机检查错误，不输出原始子进程错误中的私密数据。检查不通过时仍阻止切换，不能为了恢复操作而绕过连接隔离。绑定已保存的场景明确提示无需再次提交 API Key，重试只继续启用已保存绑定。

这不是对任意未来目录布局的保证：新布局与 PATH 均不可发现时，仍需安装有效 Codex 或明确指定 `OV_APP_CODEX`。程序能找到也不代表未来所有宿主协议兼容。

## 使用修复

从修复版源码执行 `python3 install.py --companion-only`。已有绑定保留，之后新开任务继续原绑定；如果宿主仍使用旧 MCP 进程，重启 Codex。插件在运行时固定了一份代码快照，因此磁盘文件更新不会自动改变已运行任务中的旧代码。

已安装任务可能继续使用旧快照；新的任务加载 0.2.5，必要时重启 Codex。发布包及升级说明见 [v0.2.5 发布说明](releases/v0.2.5.md)。
